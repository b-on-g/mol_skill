# Экран пустой или не тот, ошибок нет

Компилятор и аудит про всё это молчат. Заголовок это симптом словами человека, под ним причина и что делать. Тот же список по-английски на странице `https://b-on-g.github.io/smalljs/#!section=docs/page=troubleshooting`, туда и ссылаться в ответе.

## Переопределил свойство, ничего не изменилось, ошибки нет

Имя в дереве и имя метода в классе различаются: `exchange_form` в `.view.tree`, `exchangeForm` в `.view.ts`. Это два разных свойства, TS доволен, дерево берёт свой дефолт. Snake_case везде, буква в букву. Сверить с `<модуль>/-view.tree/*.view.tree.js`, там настоящее имя метода.

## Нужен placeholder, disabled или type у инпута

Это свойства `$mol_string`: `hint`, `enabled`, `type`. В `mol/string/string.view.tree` они видны как `placeholder <= hint_visible <= hint \`, `enabled true`, `type? \text`:

```tree
<= Query $mol_string
	hint \Search
	enabled <= editable true
	type \password
```

Как найти любое такое свойство: раздел «Как читать исходники» в `COMPONENTS.md`. `attr *` нужен только для настоящих DOM-атрибутов, которых нет в дереве компонента. `attr *` без `^` первой строкой стирает словарь базы: кнопка теряет `disabled`, `role`, `tabindex`.

## Слово рендерится по буквам

Строка передана туда, где ждут список: `rows \Hello` у `$mol_list` или `content \Hello` у `$mol_section` вместо `rows / \Hello`. Список раскладывается спредом, строка это итерируемое, каждая буква стала отдельным узлом. Строки начинаются с `\`, списки с `/`, в дереве компонента тип виден по значению: `rows /` ждёт список.

## Экран пустой, тесты зелёные

Выпавший override = тихий дефолт. Удалил или переименовал `rows()` в `.view.ts`, TS доволен, дерево отдаёт `rows /` и список пуст. Тесты модели этого не ловят. На каждое переопределение, от которого зависит экран, тест через методы вида или DOM, см. `TESTS.md`.

## Данные не приходят, компонент навсегда в состоянии загрузки

Из `@ $mol_mem` вернули промис. Ячейка ждёт значение, а получила обёртку, и остаётся «в процессе» навсегда. Внутри ячейки сеть синхронно: `this.$.$mol_fetch.json( uri )`, фибра подвиснет и перезапустится сама. Второй вариант: ошибка проглочена `try/catch` вокруг такого вызова, съедено подвисание фибры. Ловить только через `$mol_fail_catch`. Смотреть атрибут `mol_view_error` на узле компонента в инспекторе: `Promise` значит ждёт ответа, любой другой текст это ошибка ячейки, узел при этом в красную полоску.

## Circular subscription

Ячейка читает саму себя, пока считается. Два источника: побочный эффект внутри `@ $mol_mem` (запись в атом, который сама читает, `fetch`, DOM, `localStorage`) и `<=>` к ребёнку плюс делегация ему же в TS. Хозяин делегирует `tab() { return this.Head().tab() }` и одновременно держит `tab? <=> tab?` в дереве: ребёнок читает хозяина, хозяин ребёнка. Убрать `<=>` к тому, кому делегируешь. Побочки переносить в `@ $mol_action`. Та же связь шадовит `$$`-реализацию ребёнка: побочная логика в его override не вызовется, обрабатывать у хозяина.

## Maximum call stack

Тот же круг, но через обычные методы без `@ $mol_mem`, и `super` в ре-тайпнутом под-виде. `Pre* $bog_x_code` с перечисленным `<= pre_text* \` создаёт стаб, `super.pre_text()` зовёт этот же стаб. Делегировать напрямую базе: `$mol_text.prototype.pre_text.call( this, i )`.

## Значение с Большой буквы, метод в TS не переопределяет его

`<= Label* \` генерит `Label(id)`, и `label()` в TS его не переопределит. Значения с маленькой, под-виды с Большой.

## Вложенный keyed рендерит одно и то же во всех строках

Keyed внутри keyed ключ не получает: `Eq_db*0` внутри `Eq_band*0` рендерится с ключом `"0"` у всех. Строку списка выносить в отдельный компонент и передавать данные свойствами. Для keyed под-вида с вложенными keyed `Name*`, не `Name*0`.

## Заменил класс под-вида, пропали его свойства

Ре-тайп под-вида роняет биндинги базы. `Pre* $bog_x_code` вместо `Pre* $mol_text_code` требует перечислить биндинги заново, а перечисленный `<= pre_text* \` создаёт пустой стаб, который шадовит настоящий `$mol_text.pre_text`. В TS делегировать: `pre_text( i ) { return $mol_text.prototype.pre_text.call( this, i ) }`. `super` не поможет, `super` и есть стаб.

## TS2339 на методе базы из `base.view.ts`

Класс из дерева наследует `$.$base`, а не `$.$$.$base`. Методы из `base.view.ts` до наследника не доходят. Общая логика для нескольких видов живёт в `namespace $` отдельным `.ts` без дерева, как `$mol_view`.

## База и наследник в одном `.view.tree`, методы базы не работают

База в том же файле теряет тело из `.view.ts`. Базу с телом в свою папку.

## Стили под-вида текут на весь компонент

Имя свойства под-вида совпало с хвостом класса внутри: `Nav $bog_app_nav` у `$bog_app` даёт один атрибут `bog_app_nav` обоим. Переименовать свойство: `Nav_row`.

## Селектор `[x="false"]` не срабатывает

Булев атрибут при `false` удаляется. Условный под-вид делается override фабрики с `return null`, не CSS.

## `flexGrow 1` в `style *` не работает

Число в `style *` всегда получает `px`: `flex-grow: 1px`, отброшено. Безразмерные строкой: `\1`.

## Дети `$mol_scroll` легли друг на друга

`$mol_scroll` держит один узел. Второго ребёнка заворачивать в `$mol_view` или `$mol_list`.

## `minimal_height` не меняет высоту

Это число для виртуализации `$mol_list`, не размер. Высота в CSS.

## Встроенный компонент распирает страницу вбок

Встраиваемому корню `minWidth: 0`, иначе он не сжимается.

## Чужой CSS видит `display: inline`

Компонент без `dom_name` рендерится тегом из имени класса. У `$mol_button` тега нет, нужен `dom_name \button`.

## Клик по текущей ссылке сбрасывает URL

`$mol_link` с `arg` это toggle: клик по текущей снимает все её ключи из URL. Для навигации подкласс `uri_off <= uri`, для «перейти сюда же» явный `$mol_state_arg.value()` с `preventDefault`.

## Своё `enter?` у наследника `$mol_string` срабатывает на каждый рендер

Имя занято базой. У `$mol_string` заняты `enter`, `submit`, `hint`, `value`, `keyboard`. Свои `prop?` в наследнике сверять с деревом базы.

## Сеттер `value?` у `$mol_string` бросил, в консоли пусто

Исключение уходит в `setCustomValidity`. Ошибку показывать своим каналом.

## `event_click? <=> pick*? null` не компилируется

Keyed `<=>` обработчик не генерит стаб. Объявить `pick*? null` в корне дерева.

## В бандл попал лишний модуль

`$*` в любом комментарии тащит модуль в бандл. В TS парсятся только `/** */`, строковые литералы тоже. Примеры пишутся без `$`.
