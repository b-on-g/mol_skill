# view.tree и реактивность

## Синтаксис

```tree
$bog_myapp_app $mol_page
	title @ \My app
	body /
		<= Name $mol_string
			hint @ \Name
			value? <=> name? \
		<= Rows $mol_list
			rows <= rows /
				<= Row* $bog_myapp_row
					title <= row_title* \
```

| Знак | Смысл |
| --- | --- |
| `<=` | значение берётся у хозяина |
| `<=>` | двусторонняя связь |
| `=>` | свойство ребёнка отдаётся хозяину |
| `=` | провод между двумя под-видами: `wired = Calc result`, ровно два токена |
| `/` | список, `/string` типизированный |
| `*` | словарь |
| `@` | локализуемая строка |
| `\` | сырая строка до конца строки |
| `?` | изменяемое свойство |
| `Name*` | по одному экземпляру на ключ |
| `^` | наследование словаря базы |
| `null` | убрать под-вид |

`$mol_view` по умолчанию `display: flex` в строку. Всё, что не задал, тянется и расползается.

## Правила, которые ломаются молча

Компилятор и аудит про них молчат, экран просто пустой или не тот. Список симптомов с причинами и исправлениями в `TROUBLESHOOTING.md`.

## Цена заимствования

Имя класса это путь, и в граф попадают все папки пути. `$bog_app1_button` из `bog/app1/button/` тянет `bog/app1/` вместе с корнем приложения и всем, на что он ссылается. Тот же компонент в `bog/button/` рядом с `app/` тянет только себя. Замер: 995 КБ против 138 КБ.

```
bog/myapp/app/     приложение
bog/myapp/nav/     переиспользуемое рядом
```

Код на уровне `namespace`, вне класса, исполняется у всех, кто затащил модуль. Активацию роутера и прочие эффекты в `static {}` класса приложения.

## `@ $mol_mem`

Чистое вычисление. Читает атомы, создаёт объекты, возвращает значение. Пересчитывается при смене зависимостей.

Нельзя: писать в другие атомы, `async`/`await`, `fetch`, `setTimeout`, DOM, `localStorage`. Любое из этого даёт `Circular subscription` или зависание.

- **Возвращать промис нельзя.** Ячейка навсегда «в процессе». Волокно ради эффекта заводится через `$mol_wire_async( this ).work()`, наружу возвращается флаг или ключ.
- **Сеть синхронно:** `this.$.$mol_fetch.json( uri )` внутри ячейки. Фибра подвиснет и перезапустится сама, пока ответ не придёт. Без try/catch вокруг.
- **Голый `setTimeout` течёт** за пределы жизни компонента. `new this.$.$mol_after_timeout( ms, cb )`, он отменяется при уничтожении.
- **Ячейку, которую никто не читает в рендере, $mol сметает.** Значение откатывается к дефолту без ошибки. Состояние только для обработчиков держится обычным полем класса.
- **Эффект возвращать и читать из `auto()`.** Тело нечитаемой ячейки не выполняется вовсе.
- **Голый класс из ячейки клеймится** и рендерится не в свой тег. Заворачивать: `return { Root: Klass }`.
- **`@ $mol_mem` на делегате в реактивное хранилище вреден.** `foo( next ) { return this.Foo( next )?.val( next ) }` без декоратора, `val()` внутри уже ячейка.
- Ловить ошибку внутри ячейки только через `$mol_fail_catch`, иначе съешь подвисание фибры вместо ошибки.

## `@ $mol_action`

Обработчики событий. Дерево генерит `click? <=> submit? null` как `@ $mol_mem` на базе, в `$$` переопределять с `@ $mol_action`.

```ts
@ $mol_action
submit( next?: Event ) {
	this.ready()
	const root = this.root()
	if( !root ) return
	root.Kids( null )!.make( null )
}
```

- **Подвисающие чтения первыми.** Обработчик обёрнут в `$mol_wire_async` и перезапускается с начала, если бросил промис. Мутация до промиса выполнится дважды, а `if( !root ) return` до промиса молча съест клик.
- **Недетерминированное вычислять один раз** до фибры: `Date.now()`, `getAsFile()`, `new File()`. Иначе каждый ретрай создаёт новую сущность.
- Тяжёлую работу выносить в обычный метод и звать `$mol_wire_async( this ).save( stable_args )`. Целевой метод без `@ $mol_action`.

## Эфемерное состояние между событиями

`drag_id? \` в дереве сбрасывается между `pan_start` и `pan_move`: каждый обработчик убивает фибру предыдущего, а с ней подписку. Такое состояние держится обычным полем:

```ts
drag_id_raw = ''

override drag_id( next?: string ) {
	if( next !== undefined ) this.drag_id_raw = next
	return this.drag_id_raw
}
```

Реактивное `prop?` уместно, когда значение читает рендер.

## Роутинг и контекст

- Параметры URL: `this.$.$mol_state_arg.value( 'page' )`. Ссылки через `arg *`.
- `$mol_book2_catalog` даёт master-detail с роутингом: `param \fund`, `Spread* <= Fund_page*`, `spread_ids()`.
- Доступ к инстансу приложения снаружи: `$bog_myapp_app.Root( 0 )`. Метода `.bound()` нет.
- Внутри `namespace $` голое `new $mol_after_frame` компилируется в локальную переменную, подмена через `$` его не достанет. Сервисы только `this.$.X`.

## Отладка

- `<модуль>/-/web.audit.js` после сборки, чинить всё. Зелёный аудит не ловит порядок загрузки, шадовинг и выпавшие override.
- Сгенерированный класс лежит в `<модуль>/-view.tree/*.view.tree.js`. Там видно настоящее имя метода и что он возвращает.
- `Circular subscription`: побочный эффект внутри `@ $mol_mem` или `<=>` плюс делегирование. `Maximum call stack`: тот же круг без ячеек. Разбор в `TROUBLESHOOTING.md`.
- PWA на одном origin: свой `manifest.json` в модуле с `id` и `scope: "./"`, мержится с автоматическим.
